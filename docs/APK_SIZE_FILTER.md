# APK 资源过滤

仅正式 App 构建启用。通过项目根目录的 HBuilderX CLI 工作流或 `npm run build:app` 构建时，在资源复制完成后排除已审计、当前未使用的资源副本。

- 不修改 `src`、页面注册、业务 JS/CSS、动画、原生库或开发资源原文件。
- 排除未引用的图标原稿、仅开发玻璃测试页使用的照片和图片说明。
- 排除当前未使用的富文本、地图页面、扫码和自动化测试辅助文件；发现相关功能引用时自动保留。
- 保留输入选择器、框架运行库、教务导入文件、许可证、普通示例课表及玻璃实时预览。
- 开发／watch／H5 构建不启用。正式构建保留了开发页面的 JS/CSS；它们仍受原有开发开关控制，不做源码裁剪。
- 只允许删除已知生成目录内的明确文件，不递归删除目录；输入为符号链接、输出目录不明确时跳过过滤。

需要恢复完整打包资源时，在构建进程设置环境变量 `LAKESIDE_APK_PRUNE=0`。新资源若使用动态拼接路径或封装的动态 API，须同时审查 `scripts/apk-release-prune.mjs` 中的保留条件。

原 APK 压缩后的候选资源合计约 0.411 MiB。实际新版 APK 的差值须重新打包后测量；构建日志报告的是压缩前资源大小。

此次验证：过滤前后构建分别为 35／20 个文件，仅减少 15 个资源副本，共 743,597 字节（726.2 KiB）。`src` 整体哈希不变；业务 JS、CSS、配置和保留资源逐字节一致。最终构建的 renderjs 仅有两个独立模块输出顺序不同，各模块内容逐字节一致。脚本语法检查、应用类型检查和 295 项测试通过。原文件仍在源码目录中，设置上述环境变量即可恢复完整资源构建。
