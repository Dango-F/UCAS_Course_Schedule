## 版本一：现有三面板方案优化

入口：`src/components/CalendarSwipeView.vue`；控制器：`calendar-swipe-engine.js`。

- 保留三面板、周数据缓存、切周后复位的整体设计。
- 跟手位移和松手 CSS 动画统一由 renderjs 视图层控制，Vue 不再交替写 transform。
- 动画中再次按下会读取当前画面位置、停止旧动画，再接续手指位移；不会回到中点重新起步。
- 复位期间保留新手势的位移和抬手事件，实际课表 DOM 就绪后接续处理。
- 4px 判方向；普通翻页距离最多 62px；至少 22px 且同向速度达到 0.45px/ms 时允许短促快划。
- 微小拖动回弹、学期边界阻尼、取消手势、点击抑制与旧动画回调失效均集中处理。
- 在稳定的根节点监听触摸，避免重建滚动容器时反复解绑手势。

## 版本二：固定周槽位 + 视图层跟手与合成动画（当前）

入口：`src/components/CalendarNativeSwipeView.vue`；动画控制器：`stable-week-motion.js`。

- 每一周拥有固定的绝对定位槽位，按真实周次顺序排列，不循环、不重排三面板。
- 保留原 swiper 的小数页距离、0.2px/ms 速度阈值和边界阻尼思路；跟手时由视图层直接更新 transform，不逐帧通知 Vue，也不读取布局。
- 不再使用内置 swiper 的 JS requestAnimationFrame 收尾。松手后只设置一次 CSS transform 目标和缓动；使用与版本一相同的缓动曲线，时长随剩余距离、速度变化（120–260ms），减少动画时为 0。
- 再次触摸从实际显示位置接续，不跳到上次目标。参考版本三，在每次松手确定目标后立即提交周次，同步周、月、日期范围和预加载窗口，不再等待动画结束或下一次触摸。
- 已挂载页面范围由 DOM 变化观察更新为缓存数值；手指按住时也能使用新准备好的页面，不再把可滑边界冻结在 touchstart 时的前后两周。仍保留未加载边界保护，避免桥接延迟时出现空白页。
- 只挂载当前周及前后各两周的课表内容，其他周保留轻量空槽，避免挂载整学期课程。
- 周选择器和箭头直接定位目标页，用修订号使旧回调失效，不重建整个翻页组件。
- 停稳或下一次手势开始时，视图层只清理完全离屏页面的滚动位置，保留原课表节点；利用固定槽位和当前位移判断离屏，不再逐张读取 getBoundingClientRect；宽度由 ResizeObserver 更新。
- 五周内容保持可绘制，取消切页瞬间的 content-visibility 切换；轨道使用 will-change:transform，页面保持绘制隔离。以额外保留两周可绘制内容换取反向接续时不临时恢复子树绘制。

版本二合成动画修改前的完整源代码保存于 `.backup/swipe-v2-before-compositor-motion-20260919-054853/`；连续切页修复前保存于 `.backup/swipe-v2-before-continuous-pacing-20260919-060316/`。这两轮没有修改版本一、三及共用课表内容组件。没有修改 node_modules，也没有让内置 swiper 和自定义控制器同时写同一条轨道。

前一轮合成动画验证曾要求收尾期间延迟周次提交且不增删任何课程节点；这导致连续打断时预加载窗口和标题更新滞后。本轮改为逐次验证连续 8 次向前和 8 次向后快划的周次，以及向前跨月时的月份、日期范围和远端预加载；允许收尾期间挂载远端页，但当前可见的两页必须保留，轨道仍不逐帧由 JS 写入。

前一轮单独性能记录为 `.artifacts/swipe-ab/profile-before-compositor-v2.json` 和 `profile-after-compositor-v2-isolated.json`：持续拖动均没有新增布局，脚本耗时下降，但帧间隔没有明确改善；连续翻页的挂载工作和布局仍然存在。桌面采样不能证明真机掉帧已经消除，需要同一手机重新比较慢拖、快划和动画中反向接续。

此项目是 App Vue/WebView 页面；「内置 swiper」不代表已经迁移为 nvue 原生渲染。手感仍与设备、WebView 和课程密度有关。

## 版本二：前两轮优化记录（2026-09-19，部分已由上面的方案替代）

- 每周的 91 个网格单元节点改为 4 个背景容器，用渐变绘制横线、竖线和周末底色；保留节次、午间/傍晚间隔及课程位置。
- 保留当前周和左右相邻周的绘制，前后第二周保持数据/DOM 预加载但使用 `content-visibility:hidden` 暂缓子树绘制。swiper-item 的尺寸和顺序始终不变；不支持该 CSS 的 WebView 退回正常绘制。
- 将页面布局和绘制限制在各自面板范围内，避免扩大绘制失效区域。
- 教师、考试、地点、冲突和卡片样式在内容或显示偏好变化时集中计算，避免模板反复生成相同信息。
- 删除 `animationfinish` 中通过更换 key 重建整张课表的逻辑。视图层只重置真正离屏的滚动容器，并检查该页面是否已被后续手势拖回视野，避免可见页面突然跳到顶部。
- 第二轮曾将内置 swiper 的固定收尾从 240ms 缩短至 180ms；当前改为上面的距离/速度自适应 CSS 收尾。

密集课表、五周预加载时，浏览器中的元素数从 2575 降到 2140（减少 435 个，约 17%）。前后两次采样中，持续按住往返拖动均无节点增删、无重新布局。连续翻页仍需替换缓存窗口远端的一周，但不再额外重建刚离开的周。

诊断记录：`.artifacts/swipe-ab/profile-baseline-v2.json`、`.artifacts/swipe-ab/profile-optimized-v2-isolated.json`。采样为桌面无头 Edge、4 倍 CPU 限速；浏览器刷新节奏与实际接受的连续翻页次数可能变化，因此不把单次耗时或帧间隔差异解释为手机帧率提升。

## 版本三：初代课表渲染 + CSS 收尾（当前）

入口：`src/components/CalendarNativeSwipeViewV3.vue`；课表内容：`CalendarWeekPanelV3.vue`。

- 保留首次重写的五周预加载和 `CalendarWeekPanelV3.vue`，每周 91 个原始网格单元、课程信息的模板计算方式均未改变；不引入版本二的渐变网格、卡片信息缓存、绘制隔离或远端页面隐藏。
- 动画改用版本二的 `stable-week-motion.js` 控制器：固定周槽位，CSS transform 收尾，缓动为 `cubic-bezier(.22,.68,.36,1)`，时长根据距离/速度调整为 120–260ms，不再是固定 240ms 的内置 swiper JS 收尾。
- 跟手和动画接续由同一视图层控制器持有，避免内置 swiper 和 CSS 同时写位置；再次触摸读取实际位置，不跳到动画目标。
- 周次、月份与预加载窗口在每次松手确定目标时同步；沿用连续切周的已加载范围更新，避免重引入每两周停顿。
- 作为控制器接入的一部分，离屏滚动位置改为直接复位，不再更换 key 重建整页；保留可见课表节点，避免干扰 CSS 收尾。
- 两版共用动画引擎、课程数据和显示偏好，但课表内容组件独立。版本三根节点和 renderjs 模块仍独立，可安全来回切换；设置标记为「初代 + CSS」。
- 本次没有修改版本一、版本二或共用动画引擎；纯初代版本三可从 `.backup/swipe-v3-before-css-settle-20260919-171111/` 恢复。

## 建议对比操作

在同一设备、同一周、同一课程密度下，分别选择三版。重点先比较版本二和版本三松手后的停稳速度，再用版本一比较整体节奏：

1. 按住缓慢往返拖动，再快速拖动，观察画面与手指的距离。
2. 快划松手后，在动画结束前立即再次滑动；再试一次反向拖动。
3. 只移动很小距离就松手，检查是否完整回弹。
4. 滚到课表底部，切换一周，再滑回，检查进入画面的课表是否从顶部显示。
5. 在第一周向右拖、最后一周向左拖，确认边界回弹。
6. 连续切换版本，检查课程详情、日期按钮、周选择器和上下滚动。

## 验证与限制

运行 `npm run typecheck`、`npm test`、`npm run build:h5`、`npm run build:app`。

运行 `node scripts/verify-swipe-ab.cjs` 会启动独立的无头 Edge，使用 CDP 发送触摸输入；不需要安装额外浏览器包。截图和报告在 `.artifacts/swipe-ab/`。脚本使用临时浏览器配置，不读取个人浏览器账户。

自动验证覆盖双向翻页、小幅回弹、动画途中接续、连续翻页、逐帧日期顺序、滚动位置、学期边界、touchcancel 和版本选择持久化。它验证浏览器行为，不能替代真机上的 90/120Hz 帧率与触摸延迟测量。

参考：[swiper 官方说明](https://uniapp.dcloud.net.cn/component/swiper.html)、[renderjs 官方说明](https://zh.uniapp.dcloud.io/tutorial/renderjs.html)。App renderjs 不支持卸载生命周期，所以另通过 DOM 离开文档的观察来清理控制器，不能仅依赖 `beforeUnmount`。
